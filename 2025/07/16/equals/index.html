# B.G FOR JAVA STRING VARIABLES

考虑到 Java 的变量分为基本类型和引用类型。在介绍 == 运算符和 equals () 方法之前，先来看看 Java 变量的底层存储机制。这里主要涉及的是 GC 堆和字符串常量池两个存储单元。

# GC 堆

JVM 回收的主要区域，因此也叫 Garbage Collection Heap（GC 堆）。创建的对象主要存放在 GC 堆中，包括实例对象、类对象、数组对象等。

# 字符串常量池

字符串常量池是 Java 中一个特殊的存储区域，用于存放字符串字面值。当创建字符串时，如果该字符串已经存在于字符串常量池中（唯一性），则直接返回该字符串的引用；否则，将该字符串添加到字符串常量池中，并返回引用。

# == 运算符

# 基本用法

  • 比较对象引用：对于引用对象类型，比较的是内存地址（是否同一个对象）

  • 比较基本类型值：对于基本数据类型，直接比较值是否相等

  • 运算效率高：直接进行内存地址或值比较

# equals () 方法

  • 内容比较：比较对象的内容 / 逻辑是否相等

  • 可重写：类可以覆盖 equals () 方法定义自己的相等逻辑
  • Object 类默认实现：与 == 相同（比较内存地址）

# 包装类缓存机制

  • 基本类型包装类：Integer、Long、Short、Byte、Character、Boolean
  • 引用类型包装类：String、Enum、Class、Date、BigDecimal、BigInteger、数组

:::warnning
在前面我们说了，基本数据类型在用 == 比较时，比较的是值，而引用类型在用 == 比较时，比较的是内存地址。但是包装类作为引用类型时，有点例外。主要原因是包装类缓存机制，这里主要涉及的是基本数据类型包装类的缓存机制。
:::

# Cache 实现


# ⚠️缓存机制下的注意事项

首先注意到， Byte 包装类缓存机制的实现是通过 ByteCache 类实现的。 ByteCache 类中定义了 cache 数组，用于缓存 -128 到 127 的 Byte 对象。当创建 Byte 对象时，如果该对象的值在 -128 到 127 之间，则直接从 cache 数组中返回该对象引用；此时，他们在方法区的缓冲池中；相似地，在 IntegerCache 、 ShortCache 、 LongCache 、 CharacterCache 类中也实现了缓存机制。但是 CharacterCache 规定了初始的缓存大小为 127+1 ，因此缓存的范围为 0 到 127 。若超出了默认的缓冲区设置范围，则将变量放置到 GC 堆中。

JVM 运行时加上参数 - XX:AutoBoxCacheMax= <size> 可以改变 cache 大小
